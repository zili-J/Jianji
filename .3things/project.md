## 基本信息

- 项目：结合 Effie 与 Obsidian 优点的写作软件（暂定名：简记）
- 目标类型：自用/学习
- 当前阶段：真实试用
- 最后更新：2026-09-22

## 想达到的结果

- 一句话目标：做一个界面像 Effie 一样简洁、文档以开放 Markdown 文件保存、可借助现有云盘同步的 Windows 写作软件。
- 谁在什么场景使用：用户本人，在 Windows 电脑上写日记。
- 做到什么变化算有用：用户愿意把日记搬进来，并持续使用至少 2 周。

## 已确认事实

- 唯一目标用户是用户本人，本项目以自用和学习为目的。
- 核心价值按优先级包括：界面简洁、文件开放、云同步。
- “文件开放”指每篇日记以 `.md` 纯文本文件保存在本地文件夹，任何工具都能直接打开；软件只是读写这些文件的壳。
- 不建设同步服务器，用户选择的日记文件夹由 OneDrive、坚果云等已有云盘工具同步。
- 参考 Effie 的极简写作体验，但不接受其格式封闭。
- 参考 Obsidian 的本地 Markdown 文件模式，但不接受其界面杂乱和启动偏慢。

## 暂定假设

> 这些是可以修改的猜测，不是已确认事实。

- 第一版只服务“打开日记文件夹 → 新建或选择一篇日记 → 专心写作 → 自动保存”这一条主路径。
- 第一版采用所见即所得的轻量 Markdown 编辑体验，输入 Markdown 语法后直接呈现排版效果；第一版不提供源码/预览模式切换。
- 第一版支持标题、正文、常用 Markdown 语法和基础快捷键，不做双链、知识图谱、插件系统。
- 启动速度应明显快于用户当前使用 Obsidian 的主观体验；暂定以普通 Windows 电脑冷启动 2 秒内进入可写状态为验收目标。
- 云盘冲突主要交给现有云盘处理，应用至少不能静默覆盖外部修改。

## 当前裁决

- 结论：可以做
- 原因：这是清晰、反复发生的个人场景；最关键的价值可以通过用户本人真实使用验证；本地 Markdown 与云盘文件夹均可用成熟技术实现。
- 最便宜的下一步：先做只打通“选择文件夹、新建/打开 Markdown 日记、编辑、自动保存”的 Windows 最小版本，然后用真实日记连续试用。
- 继续/停止的判断线：能稳定写入标准 `.md` 文件且用户愿意把真实日记迁入，则继续；若核心路径仍比直接使用现有工具更打扰写作，则先调整体验，不扩展功能。

- 2026-09-20：**流畅度优化**（用户反馈切换专注模式与滚动卡顿）。先量后改，结论是瓶颈在跨语言调用与窗口操作，不在 Python 逻辑。做法：可见行只走一遍并分发给四个边栏模块；解析结果随文本一起缓存（`_doc_blocks` 等），滚动时不再重新 parse；光标换行只换两行的标签（轻量刷新）；几何签名与画布几何都做缓存，没变就不重画；几何请求用 `after_idle` 合并；留白在 `<Configure>` 里**同步**改好（Tk 的重折行排在空闲阶段前头，晚一步就会折两遍）；**取消逐帧 `lift`**，改靠创建顺序保证叠放（一次滚动少 15 次窗口重排）。649 行文档：光标换行 54.3 → 6.3 ms、滚动重画 33.8 → 3.0 ms、整篇重解析 54.3 → 20.7 ms。自动化测试增至 287 项。
  **记下来的硬约束**：Tk 里 `lift`（重排窗口）比普通调用贵两个数量级；**移动一个子窗口约 0.5 ms**，装饰画布数量就是滚动成本的量级；`_tkinter.tkapp.call` 只读，但控件的 `tk` 属性可换代理来做调用计数。
