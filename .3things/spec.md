# 产品三件事 · 当前有效规格

> 状态：第一版规格已确认，可进入实现。除“暂定”项外，其余来自用户已确认信息。

## 1. 要解决的问题

用户想在 Windows 上长期写日记，但现有选择各有明显阻碍：Effie 界面简洁，却使用封闭格式，用户无法直接掌控原始文档；Obsidian 使用开放的本地 Markdown 文件，但界面元素多、启动体验偏慢。

“简记”要提供一个安静、快速的写作外壳，同时确保每篇日记始终是用户可直接查看、复制、备份和用其他工具打开的 `.md` 文件。

## 2. 给谁、在什么场景

- 用户：用户本人，唯一目标用户。
- 平台：Windows。
- 场景：日常打开软件，新建当天日记或继续编辑已有日记，写完即可离开。
- 数据位置：用户自己选择的本地文件夹；该文件夹可以位于 OneDrive、坚果云等云盘同步目录中。

## 3. 做到什么算成功

- 核心成功证据：用户愿意把真实日记搬入，并连续使用至少 2 周。
- 数据底线：所有正文均为标准 UTF-8 Markdown 文本，可脱离“简记”直接打开。
- 体验底线：写作主界面保持克制，核心路径不被设置、知识管理或插件入口打断。
- 性能目标（暂定、可改）：普通 Windows 电脑冷启动后 2 秒内进入可写状态。
- 可靠性底线：正常编辑和退出不丢字；遇到外部文件变化时不静默覆盖。

## 4. 本次要做

第一版只做一条完整主路径：

1. 首次启动时选择一个日记文件夹。
2. 显示该文件夹内的 Markdown 文档列表。
3. 新建当天日记，默认文件名为 `YYYY-MM-DD.md`；若已存在则直接打开。
4. 打开一篇 Markdown 日记并编辑。
5. 自动保存到原 `.md` 文件。
6. 关闭并重新打开软件后，恢复上次使用的文件夹和文档。
7. 检测当前文件被其他程序或云盘改动的情况，提醒用户重新加载或另存，不能直接覆盖。

## 5. 可验收要求

- 当首次打开软件时，用户可以选择任意有读写权限的本地文件夹；验证方法：选择普通文件夹和云盘同步文件夹各一次，均能进入写作界面。
- 当文件夹中已有 `.md` 文件时，用户可以从列表打开并看到原内容；验证方法：用记事本预先创建 UTF-8 Markdown 文件，再由“简记”打开核对。
- 当用户新建今日日记时，软件创建 `YYYY-MM-DD.md`；验证方法：在资源管理器中确认文件真实存在，并可用记事本打开。
- 当用户输入文字后，内容会自动写入原文件；验证方法：不点“保存”，等待自动保存完成后使用另一工具查看文件内容。
- 当用户退出并再次打开时，可以继续上次的文件夹和文档；验证方法：重启软件并核对恢复结果。
- 当外部工具修改当前文件时，软件会提示冲突并提供安全选择；验证方法：写作过程中用记事本修改同一文件，确认不会静默覆盖任一版本。
- 当文件包含中文、常用标点和常用 Markdown 时，保存后内容不乱码、不擅自改写；验证方法：准备固定样例，编辑保存后逐字核对。
- 当文件夹不可写或文件保存失败时，软件明确提示且保留编辑区未保存内容；验证方法：使用只读文件进行测试。

## 6. 本次明确不做

- 不建设账号体系和同步服务器。
- 不内置 OneDrive、坚果云等云盘 SDK；只读写用户选择的文件夹。
- 不做移动端、macOS 或 Web 版。
- 不做双向链接、关系图谱、插件系统、发布平台、团队协作。
- 不做复杂知识库管理、数据库或私有文档格式。
- 不自动搬迁或批量修改用户现有日记。

## 7. 暂定假设、风险与安全边界

- 已确认：第一版采用轻量所见即所得的 Markdown 编辑体验；输入标题、加粗、列表等常用 Markdown 语法后直接呈现排版效果，同时保存结果必须保持为标准 Markdown 文本。
- 第一版不提供源码模式或预览模式切换。
- 暂定：文件列表先支持一层目录或简单树形目录，不做标签和高级搜索。
- 风险：云盘可能产生冲突副本或在同步时改动文件。软件需监听外部变化并避免静默覆盖，但不负责替代云盘的冲突解决机制。
- 风险：自动保存若直接覆盖原文件，异常退出可能损坏内容。实现时应采用临时文件写入后原子替换，或同等安全策略。
- 安全边界：日记内容只在本机文件系统中处理；不上传到“简记”自有服务器，不加入遥测或内容分析。

## 8. 现有项目约束

- 当前项目目录为空，尚无既有代码或技术栈。
- 目标系统是 Windows。
- 优先保证启动快、安装包克制、数据透明，而不是追求跨平台。
- 任何技术方案都必须直接读写普通 Markdown 文件，不能把数据库作为正文的唯一事实来源。

## 9. 最小版本与实现顺序

1. **文件闭环**：选择文件夹、列出 `.md`、打开、编辑、安全保存。
2. **日记闭环**：一键打开或创建当天日记，恢复上次位置。
3. **可靠性**：自动保存状态、保存失败保护、外部修改提醒。
4. **极简体验**：精简界面、键盘操作、启动性能优化。
5. **真实试用**：导入少量日记，连续使用 2 周；期间只修复妨碍主路径的问题。

## 10. 验证与撤回方式

- 开发验证：使用临时测试文件夹和无隐私样例文档，不直接拿真实日记做早期测试。
- 首次真实试用：先复制少量日记到单独文件夹，确认保存与云同步稳定后再决定是否迁入更多。
- 试用记录：每天只记是否使用、是否发生丢字/冲突、是否因为体验问题改用其他软件。
- 通过线：连续 14 天中大多数日记由“简记”完成，且无丢字或静默覆盖。
- 调整线：愿意继续使用，但频繁需要绕路或回到其他工具；只改主路径问题，不扩功能。
- 停止线：即使主路径稳定，用户仍不愿把真实日记迁入，说明该形态没有解决实际阻力。
- 撤回方式：软件不接管格式；停止使用后，整个日记文件夹仍可由任意 Markdown 工具继续打开。
