## 第 10 轮：导出长图「逗号后异常换行」= 缩进续行没并进上一段

> 在编辑页面，如果缩短行宽，逗号后面的文字也会自动换到新的一行，
> 而导出长图时，行宽很窄，所以会有异常换行的问题。

### 先证伪「行宽太窄」

- 导出图每行 29 字（1080px 画布 / 边距 72 / 正文 32px → 内容 936px）。
- 1080px + 32px 都不动时，每行上限 33 字（边距得压到 12px）；实测边距 72→12
  （29→33 字）短尾巴只从 **45 降到 41**——**没用**，别再走这条路。
- 用户文稿过半的行超 29 字，所以折行本身是必然的。

### 真因

`build_export_rows` 逐行建 `Row`，**不做 Markdown 的惰性续行**。列表项写成两行、
第二行缩进两格时被从中间截断：第一行末尾正好是逗号，第二行（丢了缩进、还带着
两个前导空格）另起一行 → 「逗号后面的文字换到新的一行」。
规模：使用说明 60/509 行、`project.md` 178/287 行。

### 改法

- 加 `absorber`：`text` 行 + 行首空白 + 上一行非硬换行 → 并进上一段并去掉缩进。
- `absorber` 只在 text/bullet/task/ordered/quote 之后保留；空行/标题/分隔线/代码/表格
  之后清空。缩进的 `- ` 是下一层列表项，不吞。
- 英文之间补空格、中文之间不补（`ord > 0x2E80` 判宽字符）。
- 硬换行的续行不并，但行首缩进照样去掉。

### 核验

- 使用说明该段重出后三行都是列表续行、都 99.6% 填满；长图 38213 → **36293px**。
- `test_export.py` 75 → **86 项**（新增 `ContinuationJoinTests` 11 项）；
  块对齐测试的判据跟着改成「按同一套吸收规则对账」。
- 用户文稿零缩进续行 → 只影响我写的两份文档。
- 新工具：`_probe_wrap_fill.py`、`_probe_rows.py`、`_probe_join.py`、`_probe_orphan.py`、
  `_render_doc.py`。

### 顺带查清：第一张为什么 31455 > 上限 30000

- 恒等式实测成立：**真实高度 = `span + 2×margin`**，`span = 末行 top+height − 首行 top`。
- 差额来源**不是表格**，而是 `_split_chunks` 只累加 `line.height`，**没算** `build_layout`
  已经烘进 `top` 的 `head_gap`（标题与分隔线的上下留白）：说明里 39 个标题 + 2 条分隔线，
  ×2×`head_gap` = 820px（默认值下）。

- **决定不改判据**：这是有意留的余量。改成按 `span` 卡，会把只超 1.7% 的文档切成两张，
  得不偿失；上限存在的理由是省内存，多 1645px ≈ 7MB，无所谓。

## 第 11 轮：编辑区「引用中英混合/插空格会换行」= 控件 `wrap="word"`

> 1. 引用有中英混合时，会出现换行。
> 2. 文字间插入空格，会出现换行。
> 3. 现在编辑区的显示比例逻辑已经不对了，进行复原。

- 先问清楚：**1、2 在编辑区（屏幕上）**，不是导出长图；3 指**正文块宽度（行宽）**。
- 1、2 是同一个 bug：Tk `word` 折行把「空格分隔的一串」当**不可拆的词**。纯中文整行没空格 →
  那个词就是整行 → 放不下只能按字符断 → **反而填得满**（99.3%）；行里只要**有一个空格**
  （中英混排带出来的也算），空格后那串中文就成了一个词 → 放不下**整串挪到下一显示行**，
  本行右边空一大块。
- 实测（`tools/_probe_editor_wrap.py`，可用宽 571px，逐显示行墨迹 ÷ 可用宽，去掉行尾分隔空格）：
  `短 后面这一整串中文…` 第一显示行 **4.7% → 96.0%**（3→2 显示行）；
  `> 引用开头 English …` **41.9% → 100.0%**；`- 列表开头 English …` **41.9% → 100.0%**；
  纯中文对照两模式都 99.3%（量法可信）。探针阈值 90%（折行落在空格上时本来 94.6–95.6%，
  用 95% 会误报）：`word` **4 处**异常 → `char` **0 处**。
- 改法：`app/main.py` 建 `Text` 那一行 `wrap="word"` → `wrap="char"`，一行，注释写全证据防回退。
  代价：英文单词跨行会从中间断（`wor|ds`）；中文优先可接受，且导出长图本来就按宽字符断行。
- 3 的机制**没坏**：`tools/_probe_editor_ratio.py` 全矩阵（窗口 820–1700dp × 30/60/80%）
  实测 30.1% / **60.2%** / 80.2%，偏差 ≤0.2%；基准是编辑区那一列（`editor.master`），
  和 spec、测试（`content_left = app.editor.winfo_x() + app._current_pad`）一致。
  观感差是**某一显示行只填 4.7%**（右边一大片空白）造成的错觉。
- 大简化：`word` 下 `dlineinfo("2.0")` = `(189,51,0,16,8)`（宽 0 的空盒子——整个「空盒子」坑类的来源）；

  **`bbox` 给的是 chunk 盒子、不是显示行盒子，那条坑仍成立。**

## 第 12 轮：编辑区显示比例改成以**屏幕**为基准 + 软件最小宽度

> 1. 无论是否在专注模式，当整个编辑区占屏幕比例超过 内容行宽比例+10% 时，文本区按设定的
>    最高比例显示，两侧平均分配空白。
> 2. 当编辑区小于 内容行宽比例+10% 时，编辑区两侧始终各留 5%，等比例缩小。
>    软件最小宽度为屏幕比例的 40%。

- 两条其实是同一个式子：`T = min(r·S, C − 2×5%·S)`（S=显示器宽、C=编辑区宽、r=行宽设置），
  `pad = (控件宽 − T) // 2`。两档在 `C = (r+10%)·S` 处正好接上，没有跳变。
- 问清两件事：①「屏幕」= **显示器**（不是应用窗口）；② 最小宽度改成「**编辑区**至少占屏幕 40%」
  （按字面「窗口=屏幕40%」本机只有 1024px，编辑区剩 300px、正文 100px，没法写作）。
  于是窗口下限 = 导航栏 + 文稿列表 + 40%·S = 267+459+1024 = **1750px**。
- **副作用（要记住）**：三栏都开时 C 通常只占屏幕 40% 上下，**默认窗口落在第二档**，
  那一档 `T = C − 10%·S`，**和 `line_width` 无关**——默认窗口下行宽设置不起作用。
  要让设定值生效得把窗口拉到 C ≥ (r+10%)·S（r=50% 要约屏幕九成宽）或进专注模式。
  这是规则本身，写了测试 `test_the_setting_is_inert_when_the_editor_is_too_narrow` 钉住它。
