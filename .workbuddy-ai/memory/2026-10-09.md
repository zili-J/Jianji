### 一个前提：dmg 只能在 macOS 上产出

`hdiutil`/`codesign`/`iconutil`/PyInstaller 的 `BUNDLE` 全是 mac 专属，这台 Windows 只能**写**脚本、
**验证不了产物**。所以真正的验证路径是 GitHub Actions 的 `build-macos`：Intel + Apple 芯片各打一份，
**打完自动启动一次、等 8 秒看进程还活着没有**——这是唯一一条不需要手上有 Mac 就能证明「移植成功」的检查。
Windows 侧能验的都验了：`bash -n` 三个脚本、LF 行尾、`git add --chmod=+x` 的可执行位。

### 移植做了什么

- 新增 `app/platform_support.py`（只 import 标准库）：读/写创建时间（`st_birthtime` / `setattrlist`）、
  永久删除（`~/.Trash`）、状态目录（`~/Library/Application Support/JianJi`）、定位文件（`open -R`）、
  子进程无窗口标志（macOS 上传 `creationflags` 直接 `ValueError`，所以是 **0**）。
  **约定：`app/` 其余模块不许再出现裸 `sys.platform` / `os.name` / `ctypes.windll`。**
- 长图导出拆成三个文件：`image_backend_gdi.py`（原 GDI 段原样搬出）、`image_backend_cg.py`（新写）、
  `image_common.py`（平台无关的 PNG 编码）。`image_export.py` 从 1080 行降到 725 行，只在头部按平台选后端。
- `speech.py` 加 macOS 后端。**踩了一个坑**：macOS 段落一开始放在 `NATURAL_RATE`/`PARAGRAPH_BREAK_MS`
  这些常量**上面**，而 `build_say_script` 的默认参数是 `def` 执行时求值的 → 直接 `NameError`，
  整个模块 import 失败。**第一次修还修错了**：我把常量那段的小标题改了、`old_string` 和 `new_string`
  只差标题，结果常量被**删掉**而不是挪走，冒烟测试报的还是同一个 `NameError`。第二次才真正插回去。
- `main.py`：字体表按平台拆三份、快捷键主键走 `_shortcut_modifiers()`、菜单文案走 `_reveal_label()`、
  加 `__version__`（两个打包脚本正则读它）；DPI 声明与输入法字体强制在 macOS 上**保留函数但早退**，
  不假装做过。
