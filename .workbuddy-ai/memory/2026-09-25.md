### 2. 回车续号后光标丢失——Tk 会把「整行没有可见内容」的行光标退回行首

`_probe_caret_cover.py` 量出来：光标在控件 x=**189**，序号画布占 **150..204**，正被盖住。

真因不是画布太宽，而是：**一行所有字符都被 elide 时，Tk 认为这行没有可见内容，
会把插入光标退回行首**（忽略 `lmargin`）。回车续号生成的 `2. ` 整行都是记号、
全被藏起来 → 光标回到行首 → 正好在画布底下。

修法（`_style_line` 有序分支）：`body_empty and line_number == cursor_line` 时把
**行尾那个空格留在 elide 之外**（`marker_end -= 1`）。留一个空格可见，Tk 就按
`lmargin` 把光标放到正文旁（x=**227**），画布右边缘在 gap 处够不着；空格没墨迹。
**序号位置一点没动**（画布仍是 `(150, 213, 54, 51)`）。

### 4. 编辑区底部留 25% 空白

`EDITOR_BOTTOM_PAD_RATIO = 0.25`，靠给最后一行挂 `spacing3` 标签实现（显示层空白，
不进正文/存盘/导出）。不能用 `-pady`——Tk 的 `-pady` 上下对称。

`_apply_bottom_pad()` **只在「留白值变了」或「最后一行换行了」时才重挂**：
`tag_remove` + `tag_add` 会让 Tk 重排并顶歪滚动位置，打字时每字一次既慢又跳。
`open_file` 里必须 `force=True`（`delete` 已清空标签，且那里刚 `edit_modified(False)`，
`<<Modified>>` 回来时第一道判据不成立）。

实测 `说明书\project.md`、用户真实设置：**267 px / 1071 px = 24.9%**。

> 踩到的坑：`yview_moveto(1.0)` 前必须 `update_idletasks()`，否则用的是过期总高度，
> 滚不到底（截图脚本量到 `yview()[1] == 0.9519` 才发现）。

**标签挂到哪一行——踩了两次才量对。** 第一版写 `end-1c linestart` → `end`，截图看着没问题，
但 `_shot_bottom.py` 打印的 `yview = (0.903, 0.956)` 露了马脚：滚到**真正的底**时右端不是 1.0，
说明 **Tk 认的总高被撑虚**，滚动条滑块到不了底（那个范围跨了两行，`spacing3` 算两遍）。

于是写了 `_probe_pad_tag_range.py`，把「两种文稿结尾 × 若干候选范围」全量一遍。
最有意思的一条：**没有一种固定范围能同时覆盖两种文稿**——Tk 的 Text 自带「隐形换行」，
`end-1c` 落在哪一行取决于文稿是不是以换行结尾：

| 文稿结尾 | 能用的范围 | 换另一种会怎样 |
| --- | --- | --- |
| 以 `\n` 结尾 | `end-1c` → `end` | 只剩 8px（留白静默失效） |
| 不以 `\n` 结尾 | `end-1c linestart` → `end-1c lineend` | 只剩 8px（同上） |

两种都在 24.9% 留白。最终写成按情形选范围（`compare(start,"==",stop)` 判）。

> **教训**：这种「只剩 8px」是**静默**失效——`tag_add` 不报错，截图不细看也像对的。
> 凡靠标签几何生效的样式，都要有「量出来对不对」的探针，不能只看截图。
>
> **一条没能坐实的疑点**：跨两行的旧写法在探针里量到 `yview()` 右端 0.96，看着像
> 「滚动条滑块到不了底」。但把「不动标签 / 手动重挂一次」并排量后发现这个读数
> **和用例顺序有关**——排在后面的用例因为前面的滚动已经把版面算完，读数就变成 1.0。
> 所以**分不清**是范围选错，还是「版面没算完」的暂态。试过在 `open_file` 里补一次

### 顺手修掉一条「量法本身不可靠」的测试

全量跑出 1 条红：`test_wheel_scrolls_exactly_the_configured_factor` 量到 5.775 倍（应 6）。

新写的 `_probe_wheel_measure.py` 换了**不依赖分数**的量法（拿一条滚动前后都可见的行，
直接比 `dlineinfo` 的 y），真实倍数 **6.000**，三条全对（40→240、40→240、80→480）。

真因是那条测试的**量法**：它用 `|Δyview[0]| × count("1.0","end-1c","ypixels")` 反推像素，
而 **Tk 只为视口附近的行排版**，远处的行还挂着「估计高度」，所以 `count ... ypixels`
会**随滚动越量越准**（13938 → … → 27627，滚完才收敛），分母一飘结果就飘。

**并且和底部留白无关**：把 `EDITOR_BOTTOM_PAD_RATIO` 设成 0 再跑，分母一样飘
（分数反推还出现过 34.400 倍）——是 Tk 的固有行为，以前那条测试只是**恰好**在
分母已收敛的时刻采样，蒙对了。

改法：`_wheel_pixels` 改成量 `dlineinfo` 的 y 位移，取可比行的**中位数**
（最上/最下那行可能被视口边缘裁到）。测试因此更强——原来那种量法不但会报假红，
理论上也会报假绿。

## 第四批：导出长图随机增加换行

一句话反馈，根因是折行断点算法（`app/image_export.py`）。

- **旧规则**：放不下时 `_break_point` 一路退到「上一个空格」。两处坏：
  ① 断点落进**行首的空白**（Markdown 硬换行留下的两个前导空格）→ `rstrip` 后成了
  **一整行空白**；② 中文行里那个空格在十几个字以前 → 白扔大半行、常常多出一整行。
- **新规则**（`_break_index`）：从放不下的那个字往回扫，**第一个「空格」或「宽字符」**
  就是断点。放不下的正好是空格 → 断在它后面；是宽字符 → 直接断在它前面；
  扫不到（超长西文单词）→ 按字硬断。再加 `text[start:cut].strip()` 为空则作废该断点。
- 触发面：两份说明书里以两个空格开头的行共 **192 行**。
- 实测 `project.md` 685 → **650 显示行**（-2100 px）、段内空行 4 → 0、填充率最低 0.0% → 81.8%；
  `简记使用说明.md` 569 → **555 行**、段内空行 13 → 0；探针过早断行 154/551 → **9/502**。
- **全量 562 项 OK**（135.3 s）。新增 `tools/_check_export_wrap.py`（用户真实设置 +
  把 `_break_index` 临时换回旧实现做 A/B）、`tools/_shot_wrap_compare.py`（前后对比图）。
- 教训：**探针自己的判据也要复核**。`_probe_export_wrap.py` 原来没把断行处那个空格
  算进行宽（`_trim_tail` 是事后裁的），把**正确的**断行报成过早——修好后 18 个「过早」
  里 17 个是这么来的。加回空格之后才看清真正的问题。


## 第五批：选中无序列表所在行也会自动换行

用户报「修复选中无序列表所在行也会自动换行的问题」。光标进到列表行，行首记号要从
`elide` 变成显示源码，根因**两层**：

1. 记号占宽（`- ` 20 px、`- [ ] ` 54 px），正文被顶右、可用宽度变小；
2. **控件级折行方式是 `word`**——规则是「一个词在当前显示行的**剩余**宽度里放不下，
   就整个挪到下一显示行」。正文平时就是这一显示行的第一个词，只能在原地按字符断；
   记号一露出来这一行就有内容了，正文那个词被整个挪走，**显示行凭空多一行**。

**只补偿宽度完全没用**（`lmargin1` 减掉记号宽之后，实测还是 2 行 → 3 行）。
这是第一轮没找到的那一层，第一版「补偿宽度」的修法在探针上一点效果都看不出。

- 修法：新增 `syntax_marker` 标签（**必须建在 `li{n}` 之后**，Tk 后建的优先级更高，
  否则 `li{n}` 的 `lmargin` 压过补偿值），露源码时配
  `lmargin1 = 行缩进 − 记号宽度` / `lmargin2 = 行缩进` / `wrap = "char"`；
  `_line_marks` 记录变 5 元组（多一个 `indent`）；引用（`> `）一并修，有序列表不动。
- 实测 108 条（9 种行首记号 × 12 种长度）：**断点变了 99 → 0 条、显示行数变了 99 → 0 条**。
  A/B 用 `JIANJI_OLD=1` 把 `_tag_marker` 换回旧的 `_tag_syntax` 行为。
- **全量 578 项 OK**（134.7 s，上一轮 562）。新增 16 条测试
  （`CaretLineMarkerWrapTests` + 换用户设置再跑一遍的子类），把修复临时撤掉验证过：
  16 条里 8 条会红。
- 已知残留：点击后下方整体上移「`px(行高) − 字体行距`」（用户设置 16 px）。Tk 把
  **elide 的首块**当成一个「零高的显示行」、还照算一份 `spacing2`，所以记号隐藏时这一行
  会多出那一截。修复前是「多一个显示行」= 下方下移 35 px，现在只剩这一截且不再重排。
  **试过都没用**：`syntax_marker` 上的 `spacing1`（`tag_configure` 读回来是 16 但行高
  一点没变——这个**标签**选项在这套配置下根本不生效）、盖整行再加 `spacing1`（同样无效）、
  `syntax` 上取 `spacing2=0`（118 → 110 只消一半，还会波及行内 elide 记号所在的行）。
  根治要改行距模型、代价是列表行整体收紧 16 px，先留着，测试只钉上界。
- 教训一：**探针的「光标在别处」不能把光标扔到文稿末尾**——目标行会被滚出视口、
  `bbox` 全返回 `None`，量到一堆 `x=0`（旧探针就是这么废掉的）。改成停在**紧邻目标行的
  普通正文行**上：目标行仍在视口内，那一行自身没有记号、几何恒定，正好当见证。
- 教训二：**`index("N.0 + 1 display lines")` 不能当断点判据**——它在记号可见/隐藏时给的
  语义不一样（实测分别落在记号尾和自然断点）。要逐字符取 `bbox`、按 y 值切显示行。
- 教训三：**量行高必须把文稿压到一屏放得下**。远离视口的行 Tk 只挂「估计高度」，
  绝对 y 会飘（同一支探针两次跑出的基准差了 8 px，差点把结论带偏）。
- 教训四（又踩一次）：**`mark_set` 之后必须显式跑 `_refresh_cursor_line()`**，
  否则量到的是旧状态，会得出「根本没这个问题」的假结论。
- `简记使用说明.md` 第七节「正文会因此右移一个标记的宽度」已改成「记号落在左边那段缩进里，
  **正文的位置和折行位置都不会动**（引用、任务项同理）」，已同步到 `说明书/`。

## 第 9 轮：导出长图逗号换行 / 底部留白闪回 / 有序列表选中即换行

> 1. 导出长图后还是异常换行，例如在逗号后
> 2. 编辑区的空白，有一定概率在点击回车后闪回。
> 3. 分有序列表也存在光标选中该行即换行的问题

### 1. 禁则（逗号被甩到行首）

- 第 7 轮只修了「哪里能断」，没管「断得难不难看」。新增 `image_export._kinsoku(text, start, cut)`：
  断点落在**收尾标点**之前就**连同前一个字一起往前挪一格**（push-out），开头标点不许落行尾。
- **先 flatten 再 wrap**、`floor` 定在**分片边界**——否则 flatten 出来的片段会把断点拉回边界。
- 行首/行尾标点 **10/1、32/13 → 0/0**（`tools/_check_export_wrap.py`）。

### 2. 底部留白闪回：`spacing3` 标签滑出最后一行

- 空末行的标签范围只有那个换行符（`end-1c`→`end`）。在 `end-1c` 敲第一个字，Tk 把新字插在
  标签起点**之前**，起点被顶到新字之后 → `spacing3` 落不到显示行上，**267 px → 8 px 而行号不变**，
  旧判据永远修不回来。
- `tools/_probe_pad_rule.py` 量出**生效条件：标签必须包含最后一行的行首**
  （`start <= "end-1c linestart" < stop`）。判据换成 `_bottom_pad_covers_last_line()`
  （量 `tag_ranges` 真实范围 + `_index_pair`，字符串比大小是错的）。
- 重挂后范围是 `行首..end`，后续字符落在范围内部 → **每个新空末行只重挂一次**，不影响打字性能。

### 3. 有序列表选中即换行：真凶是行内记号

- 先证伪序号：探针两态给出同一组盒子，序号永远由画布绘制。
- 真凶是 `**` / `` ` `` 平时 `elide`、光标进该行就露出来 → **整行变宽**，
  `wrap="word"` 把行尾那个词整个挪到下一显示行。
- 修法 `_inline_reveal_fits()`：**整行带记号量出来仍能放进一个显示行**才露（精确判据）。
  落点三处：`_swap_cursor_marks` 的 `reveal` 门、`_style_line` 的 `_hide_inline_marks`、
  标题改走 `_tag_marker`（负 `lmargin1` 把 `# ` 挂进左留白）。
- 探针 **216 条折行全等 / 0 差异**；A/B（强制露）**66 条差异**。

### 探针的坑

- **`bbox` 给的是 chunk 自己的盒子**，elide 字符会造出**幻影显示行**（用户设置下 16 px），
  按 y 切显示行会误报「断点变了」。**量显示行必须用 `dlineinfo`**（过滤 `is_real_display_box`）。
  这条差点让我按假根因改代码。
