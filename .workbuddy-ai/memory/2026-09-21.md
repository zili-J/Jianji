# 2026-09-21

## 本轮需求

> 增加鼠标滚动时编辑界面滑动的速度为现在的两倍；增加将全文输出成一张图片的功能，宽度方便在手机上阅读，长度可以根据文章内容决定。

## 一、滚轮速度加倍

- 先量：Tk 自带的 `Text` 类绑定在这台机器上是
  `yview scroll [expr {-%D/3}] pixels`（delta=120 → 约 40 px），
  **不是**「4 个显示单位」。之前按 `yview_scroll(n, "units")` 换算会偏到 6.95×。
- 改法：控件级绑定里照 Tk 的公式算完再乘 `EDITOR_WHEEL_FACTOR = 2`，并且**必须返回 `"break"`**，
  否则类绑定会在同一次事件里再滚一遍（等于滚两次）。
- 实测：delta −120/+120/−240/+240 四档 → 2.03× / 2.03× / 1.99× / 1.99×。
- 量的时候踩过坑：短文档根本滚不动，且「向上滚」要从底部起测（否则已在顶端）。

## 二、导出长图（新功能）

- 新文件 `app/image_export.py`：纯标准库（ctypes + GDI）的**离屏**长图渲染器。
  不开窗口 → 不闪、不被遮挡、可以任意高。
  - `CreateDIBSection` 用**负 `biHeight`** 得到自上而下的 32 位 DIB。
  - `TextOutW` 是**顶对齐**，要画在基线上得自己减 `tmAscent`。
  - PNG 手写编码（zlib + CRC32，颜色类型 6），**逐行流式**压缩，不整张复制 BGRA。
- `app/main.py` 加适配层 `build_export_rows` / `export_palette` / `_export_pieces`，
  把编辑区那套解析结果转成 `Row`/`Piece`；顶栏加「导出长图」按钮（专注模式按钮顺移到第 3 列）。
- 默认：宽 1080（手机阅读）、边距 72、正文 32px；超过 30000px 自动切多张
  （`name.png`、`name-2.png`…），**一张表格的边框绝不切到两张图里**。
- 实测：说明文档 424 行 → 1 张 1080×23903（1084 KB）643 ms；
  1201 行 → 2 张 1080×31067/30908（1650 KB）1406 ms；50 行 → 1080×2766，81 ms。
  流式改写把同一张图从 159 ms 降到 81 ms，峰值内存减半。

### 三个「对齐」上的坑

1. 同一个坐标有两处消费者：`top` 给边框、`baseline` 给文字，**挪动时必须一起挪**。
2. `line_height` 与字号同单位（px），所以基线要存**绝对坐标** `y + box_baseline`，
   否则全篇文字会叠在顶部（表现是「框动了字没动」/「字全在最上面」）。
3. 编辑区靠 `elide` 藏语法记号，**图片没有 elide**，记号必须在文本层面删掉
   （`_inline_spans` 改成返回 `(spans, marks)`）。另外**代码块内容不参与行内解析**，逐字原样输出。

### 又踩到的硬约束

- `FillRect` 在 **user32**，不在 gdi32。
- **64 位句柄必须先声明 `argtypes`**，否则 ctypes 当 C int 传会 `OverflowError`。
  `tools/capture_window.py` 的 `BitBlt` 和 `main.enable_dpi_awareness()` 的 `GetDC` 都中过，
  后者是启动时偶发崩溃的隐患。
- **流式压出的字节仍要包进 IDAT 分块**。少了这层，文件照样以 PNG 签名开头、
  看图软件也能显示，但结构是坏的——只有按分块走的结构校验（`png_chunks`）能抓住。
  这个 bug 是 `tools/png_crop.py` 解不开自己刚写的图才暴露出来的。

# 四、增量重解析（长文敲字不再卡）

> 承接上面的老遗留：用户选了「长文敲字不再卡」。**这项已完成。**

## 先量再改

`tools/_bench_reparse.py`（新增）把整篇重解析拆开量（4341 行）：

```
整篇重解析中位数 79.6 ms
Tcl 调用 9183 次合计 47.2 ms（占 59%）    tag 9100 次 = 34.2 ms
Python 侧 41%：_tag_inline 21.7 / parse_block 4.2 / collect_tables 2.5 / ...
```

**贵的是 `tag_*` 调用，不是 Python 正则**，而 tag 调用次数与**行数**成正比
→ 优化方向是「不碰没变过的行」，不是把正则写快。

## 做法

`_apply_markdown_styles_incremental()`：打字先走它，返回 `False` 才退回整篇。

1. `_changed_region`：只读光标上下各 48 行（`INCREMENTAL_WINDOW`），
   改动点之前取最长相同**前缀**、之后按 `delta = 新行数 − 旧行数` 取最长相同**后缀**，
   夹出改动区。插入/删除/跨行删除都能一次算准，不用知道 Tk 内部怎么改的。
2. `_region_context`：围栏与表格是跨行语法，要**校验区外没被波及**——
   区末之后的围栏状态必须与改动前一致；表格沾边就 ±64 行（`TABLE_LOOKAROUND`）重扫。
   正文打字（无 `|`、附近无表）走跳过表格的快路，这是绝大多数情况。
3. 只重刷改动区。**Tk 会自己把插入点之后的标签跟着文本挪**，区外不用重新上色，
   只把按行号索引的缓存对齐过去。抹标签按「一个标签一次整段 range」清。
4. 整篇与增量**共用 `_style_line`** 一份上色逻辑——各写一遍迟早不一致。

## 三个真坑

1. **`\r` 不是换行。** Tk 的 Text 以 `\n` 分行，行尾 `\r` 是行内容
   （`get("3.0","3.end")` 会带回来）。原 `re.split(r"\r\n|\r|\n")` 遇到**单独** `\r`
   会多切一行（实测 33 vs 控件的 32），行号整体错位。新增 `split_document_lines()`；
   **也不能用 `str.splitlines()`**（会在 `\x0b`、U+2028 断）。**空行的 `end` 就是起点**，读回要补齐。
2. **光标行的标签名不会跟着改。** Tk 挪标签但**不改名**：旧光标行仍是
   `syntax_current`、新光标行拿到 `syntax`，两边都错。重刷范围必须**同时含新旧光标行**。
3. **位移顺序**：`_drop_line_marks`（按旧行号清）→ `_shift_line_maps`（按 delta 挪）
   → 抹标签 → 上色。反了的话新填的记录会被「挪区外记录」再挪一次（记号错位、H1 徽标消失）。

## 写测试时自己踩的坑（实现是对的，测试写错了）

- 挪光标后必须补 `_refresh_cursor_line()`，否则比出来的差异全是假的（真实使用中
  光标是方向键/鼠标挪的，会走「光标换行轻量刷新」）。
- 用 `insert` 造改动别让 Tk 丢选区：在较短行上写、`insert` 后跟 `root.update()`
  这两种写法会因为选区跨行被静默丢弃，改动根本没发生。

## 修复「中间列表滚一下，顶部空出一条」（用户报「预览栏下拉出现空白」）

- **症状**：滚到最顶部时，「全部文稿」标题和第一张卡片之间空出一条（约 107 像素），
  第一张卡片被整个推下去；滚动条看上去完全正常。
- **根因**：Tk 的 `Canvas` **只在滚动区比视口高时才夹住原点**。文档少到一屏放得下时，
  `yview_scroll(-1, "units")` 把原点推成负数 → 内容整体下移、顶部空出
  「一格 = 视口高 ÷ 10」，而 `yview()` 仍报 `(0.0, 1.0)`、滚动条是满格长滑块。
  1067 高的画布滚一格 = 107 像素，正好对上截图里那条空白。
- **修复**：`app/main.py` 新增 `_clamp_cards_scroll()`（`canvasy(0) < 0` → `yview_moveto(0.0)`），
  滚轮、滚动条命令（新增 `_on_cards_scrollbar`）、重建滚动区（抽出 `_set_cards_scrollregion`）
  三处各接一次。**Treeview 与 Text 不受影响，别乱加。**
- **排查教训**：拿真实文件夹与设置反复滚动**复现不出来**（滚到顶/底、超滚、改窗口、
  切专注模式、切子文件夹都不行）。最后是**逐像素量用户截图**才定下坐标
  （红框内是纯背景、卡片间距 18px、反推缩放 150%），再由「107 ≈ 1067 ÷ 10」锁定机制。
  → 复现不出来时，先把用户看到的那一帧量清楚。
- **验证**：`tests/test_cards.py::CardScrollBoundsTests` 5 项；
  `tools/_check_clamp_guard.py` 关掉修复后 4 项失败（`canvasy(0) = -105.0`，正好一格）；
  `tools/_shot_cards_scroll_blank.py` 出修复前/后对比图。全量 **355 项全过**（350 → 355）。
